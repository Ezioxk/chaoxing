# 程序分析与界面实现

初次分析基于本地代码 `d4816a5`；上传至用户 fork 时已整合其 `main` 的 `45d2106` 更新，并适配新版抽象题库与工厂接口。上游地址：<https://github.com/Samueli924/chaoxing>，用户 fork：<https://github.com/Ezioxk/chaoxing>。本次保留原命令行使用方式，增加独立的本地浏览器控制台。

## 现有程序做什么

这是一个 Python 超星学习通课程任务处理工具。主要流程为：读取配置 → 初始化题库与通知服务 → 登录 → 读取课程 → 选择课程 → 读取章节和任务点 → 调用对应任务处理方法 → 推送结果。

| 文件或模块 | 职责 |
| --- | --- |
| `main.py` | 命令行参数、INI 配置、课程选择、章节队列、重试与并发 |
| `api/base.py` | 账号登录、Cookie 校验、课程和章节接口，视频/音频、文档、章节测验、阅读等处理 |
| `api/decode.py` | 解析平台返回的 HTML、课程、章节、任务点和题目 |
| `api/answer.py` | 言溪、LIKE、TikuAdapter、OpenAI 兼容接口、硅基流动等题库适配与缓存 |
| `api/cookies.py`、`api/cipher.py` | Cookie 文件、登录加密 |
| `api/live.py`、`api/live_process.py` | 直播任务相关处理 |
| `api/notification.py` | Server 酱、Qmsg、Bark、Telegram 通知 |
| `api/logger.py`、`api/process.py` | Loguru 日志和命令行进度显示 |
| `app.py` | Flask 与 Celery 初始化代码；原文件没有注册可操作的页面或接口 |

运行环境要求 Python 3.13+。`main.py` 使用 Python 3.13 新增的队列关闭功能，因此只安装 Flask 并不能使整个程序兼容旧 Python。已有依赖包括 Flask、Requests、Loguru、BeautifulSoup、OpenAI SDK 等；本次界面没有新增第三方依赖，也不需要 Node.js 构建、Redis 或 Celery worker。

## 初次分析发现的问题及整合后的状态

1. **课程选择需要手动输入 ID。** `filter_courses()` 在没有匹配课程时会回退到全部课程；输入错误也可能扩大处理范围。
2. **旧版本未开放章节可能无限重试。** `d4816a5` 的 `NOT_OPEN` 分支没有递增 `task.tries`。fork 最新版本已修复该问题并附带回归测试；界面独立调度仍保留最多 3 次的边界。
3. **后台异常可能使队列一直等待。** worker 抛异常时没有在所有路径调用 `task_done()`，主线程的 `join()` 可能无法结束。
4. **原 CLI 的 `ask` 选项未形成完整交互。** 当前队列实现没有与选项描述对应的询问分支；界面不提供该选项。
5. **日志与平台记录含义不同。** 例如题库未启用时，`study_work()` 会直接返回 `SUCCESS`。因此原程序的章节处理成功并不证明平台所有任务点均已完成。
6. **平台适配仍可能变化。** 登录、页面 DOM、验证码、学校登录方式或接口变化都可能影响原模块；界面本身不会修复所有平台兼容问题。
7. **旧 Cookie 解析遇到值中含 `=` 时会失败。** fork 最新版本已支持按第一个等号切分并增加文件锁；整合时保留这些改进，同时忽略空键名。

以上记录区分初始版本与整合后的版本，并非已经用真实账号复现了每一种情况。最新上游还增加了其他命令行能力；图形界面只提供本说明列出的功能。

## 图形控制台的结构

浏览器页面 → `webui.py` 本地 HTTP 接口 → `gui_worker.py` 独立 Python 进程 → 原有 `api` 模块与 `main.process_chapter()`。

- **页面层**：`templates/console.html` 与 `static/console.css`、`static/console.js`，使用原生 HTML/CSS/JavaScript，全部资源来自本机。
- **控制层**：提供设置保存、状态查询、启动、停止、退出登录。一次只执行一个后台操作，避免账号和 Cookie 同时被多个操作改写。
- **适配层**：通过标准输入传入设置，通过 JSON 行事件返回课程、章节、日志与进度。凭据不放在进程命令行参数里。
- **调度层**：复用原任务点处理方法，使用界面自己的有界章节调度；最多重试 3 次，异常计为失败，不使用原 `JobProcessor` 的队列重试实现。
- **停止操作**：终止独立后台进程，进程中的线程随之结束。重新运行时重新向平台读取章节。

原 `main.py` 和 `app.py` 保留。`api/logger.py` 增加界面 worker 模式：由界面接收日志，避免界面 worker 同时把原始敏感输出写入原命令行日志文件。CLI 模式仍使用原日志配置。

## 页面与数据语义

| 页面 | 可以做什么 |
| --- | --- |
| 总览 | 账号状态、已载入课程数量、本轮处理计数、快捷入口、最近日志 |
| 我的课程 | 搜索、勾选课程、按课程和班级区分身份、查看章节、启动处理 |
| 运行设置 | 账号或 Cookie 登录、倍速、并发、关闭章节策略、题库、通知 |
| 运行日志 | 实时输出、按级别筛选、清空显示、导出本轮保留的日志 |
| 使用指南 | 操作步骤、状态解释、模块说明、常见问题 |

课程数据仅在账号登录后从原 API 读取；未登录时显示空状态。演示数据必须显式加 `--demo`，页面持续显示演示标识，且使用单独设置目录。

章节总数来自平台章节列表。进度表示本轮已处理的章节比例，成功表示原处理方法返回成功；跳过和失败分别累计。存在跳过、失败或没有读取到章节时，不将本轮标记为全部成功。章节预览为最近一次读取的快照，处理后可重新读取确认平台记录。

## 数据保存与验证范围

- 普通设置保存在 `.webui/settings.json`；密码、题库 Token/API Key、通知 URL/Chat ID 仅在服务进程内存保留，状态接口不返回明文。
- 界面登录会话保存至 `.webui/cookies.txt`。启用已有 Cookie 登录时可读取根目录文件并复制到界面目录；不会覆盖根目录 Cookie。
- 浏览器不将敏感凭据写入 localStorage。退出登录清除界面 Cookie、内存凭据及页面课程状态。
- 日志在内存中保留最近 1,200 条，并遮盖已知凭据及账号；原接口返回的其他平台信息仍需自行判断是否适合分享。
- 服务只监听 `127.0.0.1`，接口校验本地 Host、Origin 和页面会话令牌。该控制台面向单用户本机使用。
- 自动化检查覆盖本地接口、配置校验、凭据处理、真实子进程的演示登录/运行/停止，以及模拟原 API 的重试和部分完成统计；未使用真实账号执行课程任务。
